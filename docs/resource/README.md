# 项目资料

| 目录 | 查阅内容 | 何时更新 |
| --- | --- | --- |
| [decisions/](decisions/) | 为什么作出某个选择、影响哪些工作 | 确定或调整重要做法时，新决定链接被替代的决定 |
| [architecture/](architecture/) | 系统由哪些部分组成，数据如何流动 | 首版实现确定后，或模块边界、接口和数据流发生变化时 |

[已实现需求表](requirements/已实现需求.md)随开发记录同步更新，可按师生操作查看当前能力、已知限制和对应的验收记录。

[Phase 2 功能缺口清单](requirements/三项目全量测试对照-当前功能缺口.md)对照 2026-11-20 三个旧项目的实测结果和 `INC-001`，列出当时的 19 项待补能力，并链接到对应测试用例。

[19 项功能的优先级与轮次](plans/19项功能的优先级与轮次.md)说明从 `INC-002` 开始各轮适合一起做什么，以及哪些能力可以独立交付。[INC-002 开发记录](../开发记录/INC-002.md)保存 P2-FR-02 的验收条件与实际转交的需求。

当前已确定的事项见[版本管理与会话分工](decisions/001-版本管理与会话分工.md)。新增资料时写明对应的轮次编号，并从该轮[开发记录](../开发记录/)链接过来。
