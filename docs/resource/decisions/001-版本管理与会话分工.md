# 001 版本管理与会话分工

日期：2026-11-23

状态：已采用，对应 [SETUP-001](../../开发记录/SETUP-001.md)。

用户会单独开一个应用开发会话，同时希望能在 phase2 按轮次回滚。一次增量既改变软件，也可能改变需求说明和验收记录，回看时需要找到同一时点的两者。

沿用 `classwork-phase2/.git` 作为整个工作区的版本库。`classwork-repo/` 是普通目录，代码、测试和启动说明由专属开发会话维护。开发会话回报实际文件改动和验证结果，由审查会话核对后，把代码和资料保存在带轮次编号的提交中。审查会话负责后续的版本查找和回滚。

决策、架构、需求与计划归入 [docs/resource/](../README.md)。开发记录另外保留各轮收到的提示词、当时遇到的问题和实测效果，便于按时间复查。
