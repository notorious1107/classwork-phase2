2026-11-24 核对至 INC-010，内网应用版本为 `46cf58f`。按 INC-001 时列出的 19 个师生操作逐项对照，14 项已覆盖，4 项部分覆盖，1 项尚未实现。下表按原清单的使用场景判断覆盖范围。各开发轮次已通过技术复核，师生试用结果待补。[原始 19 项清单](../requirements/三项目全量测试对照-当前功能缺口.md) · [内网部署记录](../../开发记录/INC-010.md#内网部署)

## 下一步

1. **先做内网试用。** 教师选一个实际班级，从导入名单、预览发布走到月历查完成情况和常错题。学生试一次中途离开后续答、漏答交卷和错题订正。按所用班级、作业和操作记录反馈，在对应轮次补记用户验收。[项目进度](../../../README.md)
2. **根据试用反馈选下一轮。** 学生若仍遇到答案丢失，优先核对⑦和⑨，分别试「输入后立即返回列表」和「未保存时登录失效」。若教师或学生查记录费时，再从⑬、⑮、⑯中选出实际需要的筛选条件。下一轮范围与编号待定。
3. 学生自主注册继续保留为 Phase 3 候选，目前由教师逐个建号或按班导入名单。[已实现需求表](../requirements/已实现需求.md)

**本轮边界。** 一份新卷选一个知识点。“100 以内四则混合”是一种题型，和“把几种知识点的题按份额拼在同一卷”是两项不同的教师操作。难度分档、多知识点拼卷、整卷预览、安全重试和带漏答交卷均已在表中另有轮次。

**可以调整的顺序。** INC-003 和 INC-004 分别解决保存与批阅，排在前面是因为学生会开始做更长的卷。账号维护可穿插。预览先于难度与多选是为了让教师能在发布前看到整卷效果，三类出题本身已经由 INC-002 提供。班级常错题分析可以和个人订正分别安排，两者只共享原始作答数据。

## INC-003 验收场景

| 验收场景 | 操作与预期 |
| --- | --- |
| 不同学生的个人限时 | 给一份作业设 20 分钟。两名学生于 19:00 和 19:10 开始，各自看到剩余时间，分别在 19:20 和 19:30 到期。刷新和重新登录沿用第一次开始的时刻。 |
| 与统一截止配合 | 同一示例加上 19:25 截止，第二人只能做到 19:25。服务端在到点时停止接收首次交卷，仍可保存草稿，计为未交。留空个人时长的作业继续沿用原截止规则。 |
| 混合题按所学内容和难度生成 | 选择年级、该年级已学知识点和基础档，复算题面并核对运算范围。换成已学括号的提高档，检查括号与有效步骤确实影响解法，题面和答案一致。新题保持 100 以内整数、除法整除，排除乘 1、除 1、加减 0 或乘 0 等可跳过的步骤。历史卷仍能按原题查看、判分。 |
| 平行班的发布范围 | 一班、二班各建名单。只给一班发布时，仅一班学生能打开作业。将同一份练习发给两班，两班学生看到同一套题，教师能按班查看学生进度。原班的账号、作业、草稿和成绩继续可用。 |
| 分班统计 | 一班三人，两人分别得 80、100 分，一人只存草稿。一班应显示 2 已交、1 未交、均分 90。二班两人均未交，显示 0 已交、2 未交、均分暂无。切班后学生明细与各自人数一致。 |
