# 单轮开发记录模板

## 建档时

复制下面这段。准备原始开发提示词时，新增功能用[新增功能提示词模板](开发提示词模板.md)，修问题用[问题修复提示词模板](问题修复提示词模板.md)。用户已经发给开发者的指令直接保存原文。发给审查会话的整理要求只留在聊天里。

```markdown
# 〈轮次〉　〈本轮要实现的用户行为〉

〈建档日期〉 · 〈草稿待转交／已转交〉

## 原始开发提示词

> 〈完整正文，保留分点和例子〉

## 开发前状态

〈审查仓库起点提交、应用基线版本，以及用户当时能做什么、在哪一步遇到问题〉
```

## 收到开发交付后

再把以下三节追加到同一份记录中。

```markdown
## 发送记录

〈按实际顺序记录发给应用开发者的指令。首条确认照发时可写“第 1 次沿用上方原文”。改写、补充和纠正保留实发原文。实发文本未回传时注明。〉

## 开发经过

〈结合交付版本和文件差异，记录实际改了哪些文件和行为。影响实现的取舍、遇到的问题、修正和重试结果按发生顺序写。〉

## 实现效果与验收

〈按提示词中的场景写明操作或命令、预期、实测和结论，标明已知限制。技术验证和用户试用分别记录，用户尚未试用时写“待用户验收”。〉
```
