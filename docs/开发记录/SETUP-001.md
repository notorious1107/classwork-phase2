## 起点与验收条件

起点提交为 `6fbc9cc`。当时的 Git 仓库已建在 `classwork-phase2/`，应用目录里只有 README。根协作约定提到了提交要求，但没有指明由哪个会话执行。文档目录里只有初始化记录和单轮模板。

- 从应用目录进入的开发会话能够找到自己的职责和交付方式。
- 审查会话可以用同一个版本找回当轮的代码与文档。
- 从进度页可以定位到决策、架构、需求和计划四类资料，四个目录均能随 Git 检出。

## 实际改动与执行经过

1. 检查现有 Git 布局，确认父仓库已跟踪应用目录。更新根 `AGENTS.md` 和进度页，把逐轮提交和回滚明确交给审查会话。
2. 在 `classwork-repo/AGENTS.md` 写入开发会话的工作范围和交付内容，并从应用 README 链接过去。代码和测试由开发会话交付，审查会话核对文件、验证结果和提示词。
3. 新建 `docs/resource/` 的四类目录和索引，将本轮已确定的做法写入[决策记录](../resource/decisions/001-版本管理与会话分工.md)。另外三个目录用占位文件纳入 Git，首版确定后再填写产品内容。首次批量创建时空文件的补丁格式有误，修正后核对了四个目录的内容。
