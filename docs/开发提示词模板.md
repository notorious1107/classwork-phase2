# 开发提示词模板

把自己放在收到反馈的开发者的位置，像给一起做项目的同事发消息。先看反馈来自学生还是老师，再说他们做什么时遇到了麻烦，希望加什么功能。具体经过和原因按需补充，对方已经能听懂就收住。

## 一条反馈怎么写

> 收到学生反馈，交卷时只知道漏了一题，还得从头找是哪道。他们希望提示里直接列出题号，点一下就能回去补。

换成老师的反馈也一样。遇到容易理解错的地方，举一个例子就够了。

> 收到老师反馈，学生转班后，回原班的成绩表就查不到他之前交的作业了。老师希望能按作业发布时的班级查成绩。比如小雨从一班转到二班，她在一班交过的卷子，还能从一班的成绩表点开。

## 几条反馈怎么放在一起

先按学生、老师分组，同一组开头交代一次来源。每个功能单独用“1、”“2、”往下写。一个功能涉及两边时，放在提出需求的一方，顺带说清另一方需要看到什么。

> 收到学生反馈，做作业时有两处不太方便。
>
> 1、写到一半遇上要重新登录，刚填的答案就丢了。希望用原账号回来以后，还能从刚才那道题接着写。
>
> 2、首页把做完的和快截止的作业放在一起，很难看出先做哪份。把还能交的作业放在一起，快到点的排前面。
>
> 老师这边也提了一个需求。
>
> 3、看班级常错题时，老师能看到哪几个学生做错了，想给他们补几道同类题却只能发给全班。希望能直接在这道题下面选学生，预览一下题目就能发。

开发者需要知道的规则写进对应那一点。比如导出成绩时，交了白卷得 0 分，没交的成绩留空，这个区别值得讲。其余测试数据和操作步骤留到验收时再展开。

确定转交的需求后，将可直接转发的正文原样放进[单轮开发记录](单轮开发记录模板.md)，标明“草稿待转交”。交付后再核对实发版本和后续补充。
