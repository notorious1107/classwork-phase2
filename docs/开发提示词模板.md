# 开发提示词模板

按平时给开发搭档提需求的口气写。每个功能都要说清**现在遇到了什么问题**，**希望加什么功能**。想得更具体时，可以举个例子，说说谁会怎么用、希望看到什么结果。有实际原因，也可以顺手说一句为什么要加。细节和原因都可选。

## 只提一个功能

> 我发现〈谁在做什么时遇到了什么问题〉。我想让〈谁〉能〈做什么〉。

需要时接一句“比如……”补充细节，或用“这样我就能……”说明原因。下面用学生查历史作业举例。

> 我发现学生没法查看自己写过的作业，所以我要加一个学生查看历史作业的功能，具体来说，就是学生可以看到自己做了哪些作业，也可以看到自己作业的错题情况，并且支持订正。

## 一次提多个功能

每个功能单独列一点，用“1、”“2、”往下写。每一点都带上对应的问题和想加的功能。比如同一轮想让学生和老师都能查历史。

> 1、学生想看看上周哪道题做错了，现在找不到以前的答卷。我想让学生能从自己的作业记录里点进去，看当时填了什么，还能把错题再做一遍。
>
> 2、老师想看看一个学生最近几次作业做得怎么样，现在得挨份找。我想让老师点一下学生的名字，就能看到他交过哪些作业、每次得了多少分。

草稿应当能单独转发。开发者需要知道的业务细则直接写进对应的功能，可以用一句“做好后告诉我怎么试”说明交付方式。轮次编号放在审查档案的标题里，转交后按顺序把实际发出的原文放进[单轮开发记录](单轮开发记录模板.md)。
