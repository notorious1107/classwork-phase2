# 小小算术 · 班级作业本

多班级数学作业网站，在[第一轮需求](docs/requirements-01.md)基础上持续实现本次对话需求（2026-11-24）。教师可批量建号、按班搜索、选专项或综合题型及难度，先预览换卷再确认发布 10、20 或 50 道计算题，并设置北京时间截止与个人限时；学生保存草稿、提交查看自动批改，用自己的错题本独立订正；教师按班查看月历、逐人成绩、已交/未交与均分，逐题回看原卷并筛选个人练习记录，也可按日期范围汇总班级学情、查看常错题和逐人原答案。学生仅能访问自己的答案与成绩，数据保存在本地 SQLite。

学生也能续做已有的乘除法和混合运算作业，师生可用原账号查看原成绩。

开发遵循 [执行规则](AGENTS.md) 和 [小步提交规范](docs/commit-policy.md)。

## 启动和停止

需要 Node.js 22.13+（本机已用 22.17.0 验证）。首次使用或更新后先安装锁定的依赖；运行时读取 Excel 名单需要 read-excel-file 和 unzipper-esm，无需配置数据库服务。

在含有 `package.json` 的项目目录打开 PowerShell，运行以下命令。

```powershell
npm ci --cache .runtime/npm-cache
npm start
```

浏览器打开 **http://127.0.0.1:5173**。`npm start` 启动两个独立进程：前端 5173、API 3001。终端按 **Ctrl+C** 停止两者。端口冲突时启动会退出，不会关闭其他项目的进程。

`npm run demo` 是可选的演示初始化：只补建不存在的演示学生；仅在尚无任何作业时添加第一份练习；重复执行不会清空数据或重置密码。只想从空班级开始时，首次启动可直接执行 `npm start`。

空库首次运行时自动建立教师账号，表中的两个演示学生由 `npm run demo` 建立。教师可在「学生名单」中继续创建账号。

## 使用顺序

1. 用教师账号登录，在「学生名单」创建班级（原有班级可修改名称），选择当前班级，再填写学生姓名、账号、至少 8 位密码和所属班级；把账号密码告知学生。也可在名单的「所在班级」调整已有学生归属。
2. 在「作业与成绩」填写名称，选择单一题型或「综合练习」、基础/提高与题量，可选填截止时间和个人限时，勾选接收班级后点「生成 / 更新预览」。检查整卷、换卷或改设置再预览，满意后点「确认发布」；学生拿到最后预览的原题和原顺序。点开作业后切换班级查看各班进度。
3. 教师退出后，用学生账号登录，打开「我的作业」。停笔约一秒自动保存。点「保存草稿」可继续填写，点「保存并离开」会等最新答案保存成功后返回作业列表，下次用原账号打开可继续。
4. 点「提交作业」检查确认。若还有空题，点确认框中的题号即可回到对应的答案框补写，也可以选择「确认按现有答案交卷」。提交后立即显示总分、每题对错、漏答与正确答案，原答案锁定。
5. 换回教师账号，打开该作业并点「刷新成绩」，切换班级查看各班每位学生的成绩、已交/未交人数和平均分。

例如要设为“明晚八点前交”，在日期时间控件选择明天的日期和 20:00；不填则不限时。设备使用其他时区时，输入与展示仍按北京时间（Asia/Shanghai，UTC+08:00）处理。

个人限时可留空，或填写 1–1440 的整数分钟。限时作业先显示准备说明，第一次点击「开始作答」才显示题目并记录个人起点；倒计时连续运行，刷新或重新登录不重置。个人到期和全班截止取较早时刻，到点仍能保存草稿，未交仍计为未交。普通不限时作业保留原先直接作答流程。

「我的作业」按可提交、已截止未交、已提交分组。可提交作业里，本人最早到期的排在最前。还没开始计时的只看全班截止，没有实际截止时间的排在最后。截止时间相同的先显示较新发布的作业。

个人时间用完时，学生首页会把这份作业移到「已截止未交」，教师成绩表会在该生一行标明「个人限时已到 · 未交，不能提交」。其他学生按各自的开始时间判断。已打开的页面按服务端时间更新已知截止状态，含有待交限时作业时也会定期同步新开始和新交卷的进度。

草稿保存后仍计为未交。某题超出范围或不是整数时，页面标出题号，其余有效答案和主动清空的题照常保存。无效输入留在题框，该题在账号中保留上次保存的值。此时点「保存并离开」可返回修改，也可确认放弃无效输入并回到列表。断网或有版本冲突时会留在作业页。多位学生可使用不同浏览器或独立会话同时操作，同一浏览器的普通标签页共享登录会话。

## 自动草稿与漏题交卷

学生填写答案后停笔约一秒自动保存，数字 0 会保留。保存时可继续输入，后续修改会接着保存，不清空输入、不改变焦点。断网或回包丢失时保留本页答案并提示失败，恢复后重试；也可点「保存草稿」。作业截止或个人时间用完后仍能自动 / 手动保存，教师仍记为未交、未评分；已经交卷的答案不会被晚到的草稿覆盖。

写到一半需要重新登录时，浏览器会按账号和作业暂存尚未同步的输入。在原页面用原账号登录会直接回到这张卷，也可在同一浏览器的「我的作业」重新打开。恢复后会自动保存有效答案。如果其他窗口已经修改了草稿，页面会先请你选择使用哪一份。已经保存到账号的答案可在其他设备续写。清除浏览器站点数据会删除本机暂存，禁用浏览器存储时须在当前页面完成重新登录。

同一学生在不同窗口改同一份作业时按草稿版本检查。旧窗口不能静默覆盖新答案，页面会暂停自动保存并保留本页输入，可明确选择「载入已保存草稿」或「保留本页答案并保存」，两种操作均再次确认。重设密码后旧登录失效，尚未写入的旧会话请求不能继续保存。

交卷确认框会显示漏答数量，并按卷面顺序列出每个漏答题号。点题号会关闭确认框，光标移到该题。补答后再次点「提交作业」，列表会按当前答案更新，填入 0 也算已作答。选择按现有答案交卷时，空题作为漏答不计得分，仍按整张卷题数折算 100 分。例如 10 题答对 8 题、漏 2 题为 80 分，20 题答对 19 题为 95 分。学生原卷、教师原卷明确标注漏答，错题本收录这些漏答，班级分析单列漏答人数；学生之后订正不改变原分数和首次交卷统计。截止时间和个人限时的提交限制照常生效，允许漏题不会绕过截止。

旧手动草稿继续读取原答案。启动时只在缺少 draft_revision 时追加整数列（默认 0），已有版本字段和值不重建、不归零，原题、草稿内容、历史分数原样保留。PUT /api/assignments/:id/draft 和 POST 同路径 /submit 的新页面请求带 draftRevision，成功写入后版本增加；旧版本不同答案返回 409 / DRAFT_CONFLICT，相同内容的保存重试不重复增加版本。原有未携带版本号的客户端仍可使用旧接口；新页面所有保存与交卷均检查版本。漏题交卷额外要求 allowIncomplete=true，未明确确认时返回未答题数，不提交。

## 先预览，再确认发布

预览区显示整张卷、接收班级、截止时间、难度规则及各类题数，只有教师可见。点「换一套」可按当前设置生成新卷；点「修改设置」回到表单，调整后再点「生成 / 更新预览」。设置一旦改变，确认按钮停用，避免把旧卷按新设置发布。每位老师保存一份预览，刷新或下次登录可恢复最后一次已生成的未发布卷。

「综合练习」需勾选加减、乘除、混合中的两类或三类，题量尽量均分，余题按加减、乘除、混合顺序分配；三类 20 题为 7、7、6，50 题为 17、17、16。含混合题时可选年级和已学知识点；整张卷使用所选的基础或提高档。学生仍写一张卷、保存一份草稿、提交一次，按总题数折算 100 分。

确认发布使用已保存的预览题目和顺序，不再重新生成。重复确认或网络回包丢失后重试会回到同一份作业。另一窗口换卷会使旧预览编号失效，需要重新预览；若预览期间截止时间已到，须改时间再预览。迁入的历史预览可沿用原题确认，页面注明「沿用历史预览原题」；点换卷后才按本轮难度规则出题。已发布旧卷的原题、草稿与成绩保留。

## 批量导入学生

在「学生名单」先选择当前班级，下载页面提供的 [Excel 样例](frontend/student-roster-template.xlsx)，用本班名单替换示例行，再选择文件并点「导入当前班级」。支持 .xlsx（只读取第一个工作表）和 UTF-8 CSV，第一行须为“学号、姓名”两列；每次最多 500 名学生，文件不超过 512 KB。

- 学号必须作为文本填写，样例前 500 行已设置文本格式。00123 会按原字符串保存，账号和初始密码均为 00123；姓名相同、学号不同可以分别建立账号。学号支持 1–32 位字母、数字、下划线和短横线，姓名 1–30 字。导入后若学生填写登录密码，也须保留开头的零。
- Excel 数字学号会逐行提示改为文本，以免把已经丢失前导零的数字当成正确学号；单纯修改显示格式不能恢复已丢失的零，请核对原始学号。CSV 也须在保存前保留原始学号，推荐使用 Excel 样例。
- 有效行导入所选班级，空学号、空姓名、文件内重复学号、全系统已有账号或其他无效行均跳过，并在页面列出文件行号、学号、姓名和原因。文件内重复学号涉及的各行全部跳过。完全空行忽略，表头或文件格式错误时整份不导入。
- 导入只新增账号，不修改已有账号的姓名、密码、班级、答案或成绩。重复提交文件只会提示账号已存在；并发请求也不能覆盖已建立账号。导入结果显示后会刷新当前班完整名单。

## 当前班级搜索

导入后可在名单上方按姓名或学号搜索，支持部分匹配。两个同名学生分别展示对应的学号；显示人数为“匹配人数 / 本班总人数”，不影响作业统计。搜索只在当前班级的已加载名单中进行，换班会保留搜索词并改搜新班，旧班结果不会混入；点「清空搜索」或清空输入框即可恢复该班全名单。搜索时不会清掉已选择的待导入文件。成功导入后自动清空筛选，展示当前班完整名单便于核对。

## 修改与重设学生密码

学生登录后点「修改密码」，填写原密码及两次新密码。新密码须为 8–128 个字符；导入账号原来的短初始密码仍可作为原密码。修改成功后本窗口继续使用，其他登录窗口失效，下次用新密码登录。

教师在「学生名单」先选班、按学号核对学生，点该行「重设密码」。重设页明确显示姓名、学号 / 账号及班级，填写两次新密码后点「确认重设此人密码」，再把新密码告知本人。只更新选中学生的密码，该学生现有登录全部失效；同名学生及其他班级账号不受影响，原题、草稿、成绩、班级归属保持原样。

对应 API 为 PUT /api/me/password（学生，currentPassword / newPassword）和 PUT /api/students/:id/password（教师，classId / newPassword）。后端核对角色、原密码或当前班级，并防止并发改密覆盖及转班后误重设；密码只以独立盐的 scrypt 哈希保存，不在响应中返回。

## 教师练习月历

教师登录后点「练习月历」，选择当前班级；默认打开服务端北京时间的当前月，可用「上月」「下月」或月份输入框切换，也可点「回到本月」。月历以周一为一周起点，每个日期显示当天发布的练习份数，点击日期查看当天的作业。没有练习的日期也可查看。

作业按保存的发布日期换算为北京时间后归入日期，截止时间在作业卡片上另外显示。例如周二发布、周四截止的练习放在周二。同一天发布的多份练习分别展示本班已交人数、未交人数和平均分；平均分只计算本班已交学生，无人提交显示「暂无均分」，已交均分为 0 则显示 0。

点击作业卡片进入现有成绩明细，「返回练习月历」会保留班级、月份和日期。在月历换班保留当前月份和日期，只显示新班的作业与统计；明细页换班后返回月历也使用新班。已选的班级、月份和日期写在页面地址中，刷新仍可回到对应视图。需要更新提交进度时点「刷新月历」。本功能只读取原作业和成绩，不修改历史题目、草稿或分数，也不增加数据库迁移。

## 班级学情与常错题

教师登录后点「班级学情」，选择班级、发布日期开始和结束日期，再点「查询学情」。默认查看服务端北京时间最近七天（含今天），起止日均包含，依据作业发布日期，与提交时间、截止时间无关。任一日期可留空；点「清空日期」查看全部历史。班级、日期、选中题号和「包含全部题目」保存在地址中，刷新可恢复；换班保留日期，清掉上一班的题目明细。

概况展示范围内的练习份数、已交和未交份数、整体均分。已交/未交按学生作业份次计数，同一学生有两份作业就计两份。整体均分把所有已交原分数放在一起计算，不平均各卷均分：一份卷两人交 80、100，另一份一人交 60，整体均分为 80。没人交显示「暂无均分」，真实零分显示 0；草稿与未开始均算未交，不计入均分。可展开「核对这几份练习」查看各卷数据并进入原成绩表。

常错题按答错与已交漏答总人数降序排列，同人数时优先错漏率高的题。每题标明来源作业、原题号、发布日期及答对、答错、漏答、未交人数；相同算式在不同作业中分别统计。默认只列有错漏的题，勾选「包含全部题目」也可查看全对或尚无人提交的题。漏答指已交原记录中该题为空（包括迁入的旧记录）；草稿即使写过答案也算未交，不算错或漏答。

点题目查看本班各学生的原答案，姓名旁显示学号 / 账号以区分同名学生。已交按首次交卷判断对错；未交明确标注「未交、未评分」，仅显示最后保存的草稿，尚未保存则显示「未保存答案」。点学生姓名可回看整张原卷，返回时保留班级、日期和题号。手机上逐人答案上下排列。统计与现有班级报告使用同一名单，同卷发两班时分别计数；学生之后订正不会改变首次交卷答案或这里的讲评统计。学生转班后仍按这份作业记录的班级统计。

### 从一道常错题布置补练

在「班级学情」点开一道常错题，在逐人原答案下方勾选接收学生，点「生成补练预览」。可选择在该班这道题上答错或已交漏答的学生，勾选项显示姓名、账号和作答状态。

每份补练有 5 道新题。加减法保留原运算和进退位类型，乘除法保留原运算，混合运算保留运算顺序和括号结构。综合卷按选中的那一道题出题。核对预览里的算式和名单后点「确认发布补练」。更改名单后需重新预览；刷新再打开同一道题可恢复已生成的预览。普通班级作业的预览单独保存。

所选学生用原账号在「我的作业」领取补练，可保存草稿并交卷。补练成绩表只列本次点名的学生，每题 20 分。名单按学生账号固定，后续转班或入班不改变接收人。原卷保留首次交卷答案和分数。

教师接口 `POST /api/analytics/remedial-previews` 接收 `classId`、`assignmentId`、从 1 开始的 `questionNumber` 和 `studentIds`。服务端核对原交卷，将预览题目和接收名单一起保存。`POST /api/analytics/remedial-previews/:previewId/publish` 发布该教师的预览，重复确认返回同一作业编号。

## 查看学生原卷和个人记录

学生作业列表和教师成绩明细使用同一套提交截止规则。成绩接口 `GET /api/assignments/:id/report?classId=…` 为每位学生返回开始时间 `startedAt`、实际截止时间 `effectiveDueAt`、截止来源 `deadlineSource`（`personal`、`class` 或空）和到期状态 `isClosed`。查看列表和成绩表均不会启动个人计时。

在教师的班级成绩表中点击学生姓名，可逐题查看保存的原题、该生当时填写的答案、正确答案和对错，页头保留原分数。已提交的答案只读。只保存草稿或尚未保存答案的学生也能打开，页面明确标注「未交、未评分」，空题显示「未填」；草稿不评对错、不算成绩，展示最后一次保存时间，不包含学生尚未保存的修改。教师查看不会替学生开始计时、提交或修改答案。截止后仍能查看已交原卷及保存的草稿。

在「学生名单」选班并点击姓名，进入该生「练习记录」；同名学生可凭学号 / 账号区分，记录页也能切换当前班的学生。可填写开始和结束日期、选择「知识点 / 练习内容」后点「查询记录」，日期和知识点可组合筛选，任一条件可留空。日期按北京时间的发布日期查询，起止日均包含，与提交日、截止日无关。例如查看上周布置的乘除练习，选择上周一到周日以及「20 以内乘除」。点「清空筛选」恢复全部记录。

每条记录显示作业名、发布日期、知识点、提交状态和分数，点「查看原卷」进入该学生的原卷，返回时保留班级、学生和筛选条件，刷新也保留。混合知识点按发布时保存的配置匹配；旧作业没有细分配置时显示「未记录细分知识点」，仍可按三种练习题型查询。换班只列出新班学生的记录，保留筛选条件并默认选择新班第一名学生；空班显示加入学生的提示。例如小雨从一班转到二班后，老师在一班成绩表点她的姓名，或在二班名单打开她的练习记录，都能回看同一份一班原卷。小雨用自己的账号也可从「我的作业」的「已提交」分组打开原卷。

## 学生错题本与独立订正

学生登录后点击「我的错题本」，查看不同作业第一次交卷时答错的题，按原交卷时间倒序排列。卡片显示作业名、原题号、当时的答案和订正进度；点击作业名回看自己的原卷，对应题目用黄色边框标出。草稿与未交作业不收录，已做对的原题也不收录。同一算式在不同作业中分别保留，订正做对后仍保留来源及历次记录。转班后自己的这些已交错题和原卷仍可从错题本回看。

点击「订正」后先独立填写答案，提交后查看对错、正确答案和逐步计算过程。答错时点「再订正一次」重做原题。20 以内的一步加减法订正正确后，点「再练一次 · 换道同类题」会换两个运算数，保留原题的运算和进退位特点。例如 `18 − 5` 会换成另一道不退位减法。其他题型可点「再练这道原题」。

同类题在空白答案框中作答，提交后按新算式批改，还可以再换一题。回到错题本，已改对的加减法错题也有「同类再练」入口。错题本的「订正记录」只统计原题订正，原作业分数和教师成绩统计保持原值。

订正独立计次，原作业的答案和分数不变，也不改变教师成绩统计；已交原作业截止后仍能订正。订正历史在刷新、重新登录和重启服务后保留，再次打开订正题面会重新隐藏答案。尚未提交的订正答案只保留在当前页面，离开或退出有确认提示；断网时保留输入可重试，同一次提交的回包丢失后重试不会多记一次。

## 业务规则

- 每份选择 10、20 或 50 道题，默认是 10 道基础「20 以内加减」。可选单一加减、乘除、混合题，或综合其中两三类；专项内两种运算尽量均分，奇数题量时相差一道。
- 新专项卷均可选基础/提高。基础加减不进退位，提高加减练进位、退位；基础乘除练熟悉口诀与对应除法，提高乘除优先非平凡口诀，均保持 20 以内、整除、不重复。提高 50 题会用其他非平凡口诀补足，不扩大范围。
- 混合题可选 1–6 年级和已学知识点：连加连减、连乘连除、先乘除后加减、小括号；一年级可选加减链，二年级起可按学习进度勾选其余内容。基础 2 步、提高 3 步，只使用所选知识点，仍在 100 以内。新混合题排除加减 0、乘 0/1、除 1、同数相除，以及相邻两步直接抵消的形式。所有新题的操作数、中间结果和答案均为对应范围内的非负整数，除法整除且无零除数。
- 历史作业沿用保存的原题。「20 以内加减」和「20 以内乘除」接受 0–20 的整数，「100 以内混合运算」接受 0–100 的整数。师生看到相同的算式，例如 `24 ÷ (12 ÷ 3)`。
- 满分 100，按答对题数 ÷ 总题数 × 100 计分（10/20/50 题每题分别 10/5/2 分）；例如 20 题答对 19 题得 95 分；提交前不返回标准答案；评分和权限校验均由 API 执行。
- 草稿允许留空。交卷若有空题需明确确认按现有答案提交，漏答计 0 分，分母为原卷全部题数；提交后锁定，回看时按原答案逐题批改并标注漏答，教师汇总取已保存的分数。
- 截止时间必须晚于发布时刻。到点（含截止的这一刻）后，未交学生不能提交，但仍可保存草稿，教师统计为未交，不参与平均分。已交学生可照常回看成绩，原答案与分数锁定。是否逾期由后端时钟在收齐请求内容并校验后判断，截止前开始发送但到点后才收齐的提交也会拒绝。
- 作业确认发布时，系统为每名收到作业的学生记录班级。成绩表、月历和班级学情使用这份作业的名单。两班收到同一份卷时，每名学生只计入其中一个班。后来入班的学生仍能领取本班以前的作业，首次领到的班级作为这份作业的归属，截止限制照常生效。
- 转班后，新发布的作业随当前班级分发。先前领到的作业保留原成绩归属，老师仍可查看原卷、草稿和提交状态。学生可回看本人已交原卷，继续作答的权限按当前班级及首版旧库保留名单判断。

## 数据与配置

数据默认在 `data/classwork.sqlite`，账号密码使用带独立盐的 scrypt 哈希，会话保存在数据库并使用 HttpOnly、SameSite Cookie。账号、作业（含题型与截止时间）、草稿、成绩、订正记录、未过期会话均可在重启后恢复。升级时优先沿用已有的原班历史名单，其余作业以升级时的班级成绩名单作为起点。已经转出的学生若留有答案或开始记录，单班卷可从发布班级恢复归属。旧版多班同卷没有转班轨迹，学生仍在目标班时沿用升级时所在班级，已转出全部目标班时在个人记录标为「原班级未记录」，仍可打开原卷。启动时按需补充题型、截止、限时及练习配置字段；历史题量以保存的原题为准，历史题目、答案和分数不重写；已有 difficulty（basic/advanced/空）和 question_count 字段原样保留，不依难度重新出题，读取题量以实际保存的题目数量为准；旧作业没有截止时间时继续不限时。`data/` 不进入 Git；备份时先停止服务，再复制整个 `data` 目录，恢复时也先停服务。

要复核已有班级，请把一致性备份的工作副本放到本项目，例如 `data/review.sqlite`，在应用目录运行以下命令。使用原账号密码登录即可。新保存的草稿与提交写入这份副本。

```powershell
$env:DB_PATH = (Resolve-Path -LiteralPath 'data/review.sqlite').Path
npm start
```

可通过当前终端的环境变量设置独立资源：

```powershell
$env:WEB_PORT = "5174"
$env:API_PORT = "3002"
$env:DB_PATH = "data/another-class.sqlite"
$env:TEACHER_PASSWORD = "YourOwnPassword123!"
npm start
```

`TEACHER_PASSWORD` 只在数据库第一次创建教师时生效，已有密码不会被覆盖。默认仅监听本机 127.0.0.1。本轮没有外网/局域网发布，也未添加 HTTPS、重交、删除学生、删除班级和密码重置。

前后端可分别启动：在两个终端运行 `npm run start:api` 与 `npm run start:web`；端口配置需一致。前端为独立静态服务，使用 `/api` 代理调用后端 JSON API。前端没有数据库访问能力，后端不提供页面文件。

错题本 API 仅供学生本人使用：GET /api/mistakes 读取首次交卷时答错的题，按原交卷时间倒序；GET /api/mistakes/:assignmentId/:questionNumber（题号从 1 开始）只返回订正题面，不返回标准答案、讲解或以往订正答案。GET 同路径 /attempts 查看本人订正历史，POST /attempts 提交 {answer,requestId}，提交后返回对错、正确答案和逐步讲解；同一 requestId 重试不重复计次。GET 同路径 /original 回看该生已交的原卷，转班后也保留这一条已交记录的访问。接口不接受代其他学生订正，教师不能使用学生订正接口。

同类再练使用独立的练习记录。原题订正正确后，`POST /api/mistakes/:assignmentId/:questionNumber/practice` 携带 `requestId` 领取新题，重复请求返回同一练习编号。学生可用 `GET …/practice/:practiceId` 打开自己的练习，在同一路径用 POST 提交 `{answer}`。服务端保存生成的算式，按该算式批改。练习题面在首次作答前只提供算式、题型和来源，提交后可查看答案和讲解。

correction_attempts 表独立保存每次原题订正，mistake_practice 表保存同类再练的算式及首次提交的答案，原题、原作答、原分数和原计时起点不修改。错题本从已锁定的首次提交答案读取，草稿与未交作业不收录；相同算式在不同作业中的错题分别保留，做对后仍保留来源和订正次数。tests/corrections.test.mjs 覆盖原题与旧库兼容、逐步运算顺序、50 题题号、角色与学生隔离、并发重试幂等、原成绩不变和重启持久化。
