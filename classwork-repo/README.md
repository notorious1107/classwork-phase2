# 小小算术 · 班级作业本

单班级数学作业网站，已实现[第一轮需求](docs/requirements-01.md)：教师创建学生账号、发布 10 道「20 以内加减」；学生登录、保存草稿、提交和查看自动批改；教师查看逐人成绩、已交/未交人数及平均分。学生仅能访问自己的答案与成绩，数据保存在本地 SQLite。

开发遵循 [执行规则](AGENTS.md) 和 [小步提交规范](docs/commit-policy.md)。后续只按新发布的需求扩展。

## 启动和停止

需要 Node.js 22.13+（本机已用 22.17.0 验证）。运行服务无需安装第三方依赖，也无需配置数据库服务。

在 PowerShell 中执行：

```powershell
cd C:/Users/29791/OneDrive/Desktop/classwork-incremental
npm run demo
npm start
```

浏览器打开 **http://127.0.0.1:5173**。`npm start` 启动两个独立进程：前端 5173、API 3001。终端按 **Ctrl+C** 停止两者。端口冲突时启动会退出，不会关闭其他项目的进程。

`npm run demo` 是可选的演示初始化：只补建不存在的演示学生；仅在尚无任何作业时添加第一份练习；重复执行不会清空数据或重置密码。只想从空班级开始时，首次启动可直接执行 `npm start`。

## 使用顺序

1. 用教师账号登录，在「学生名单」填写姓名、账号及至少 8 位密码；把账号密码告知该学生。
2. 在「作业与成绩」填写作业名称并发布，自动生成全班同一套 10 道题；点开作业查看进度。
3. 教师退出后，用学生账号登录，打开「我的作业」。可部分作答后点「保存草稿」，刷新或下次登录可继续。
4. 完成全部 10 题，点「提交作业」并确认；立即显示总分、每题对错与正确答案。提交后锁定答案。
5. 换回教师账号，打开该作业并点「刷新成绩」，查看每位学生的成绩和统计。

草稿为手动保存，页面会提示未保存的修改，离开或退出前会确认。多位学生可使用不同浏览器/独立会话同时操作；同一浏览器的普通标签页共享登录会话。

## 业务规则

- 每份作业 5 道加法、5 道减法，无重复算式；操作数与结果均在 0–20 之间，减法无负数。
- 每题 10 分、满分 100；提交前不返回标准答案；评分和权限校验均由 API 执行。
- 草稿允许留空，提交要求全部填写 0–20 的整数。重复提交保留第一次结果；延迟草稿也不能覆盖已交作业。
- 作业面向全班，新增学生也能完成历史作业。人数按当前名单统计；平均分仅计算已提交学生，没有提交时显示「—」。

## 数据与配置

数据默认在 `data/classwork.sqlite`，账号密码使用带独立盐的 scrypt 哈希，会话保存在数据库并使用 HttpOnly、SameSite Cookie。账号、作业、草稿、成绩、未过期会话均可在重启后恢复。`data/` 不进入 Git；备份时先停止服务，再复制整个 `data` 目录，恢复时也先停服务。

可通过当前终端的环境变量设置独立资源：

```powershell
$env:WEB_PORT = "5174"
$env:API_PORT = "3002"
$env:DB_PATH = "data/another-class.sqlite"
$env:TEACHER_PASSWORD = "YourOwnPassword123!"
npm start
```

`TEACHER_PASSWORD` 只在数据库第一次创建教师时生效，已有密码不会被覆盖。默认仅监听本机 127.0.0.1。本轮没有外网/局域网发布，也未添加 HTTPS、多班级、截止时间、重交、删除学生和密码重置。

前后端可分别启动：在两个终端运行 `npm run start:api` 与 `npm run start:web`；端口配置需一致。前端为独立静态服务，使用 `/api` 代理调用后端 JSON API。前端没有数据库访问能力，后端不提供页面文件。

## 验证

```powershell
npm ci --cache .runtime/npm-cache
npm run check
npm test
```

只有测试需要 jsdom 开发依赖，锁文件固定依赖版本。检查和测试分别退出码为 0 后才视为通过。测试使用自动清理的独立临时数据库，不改动演示数据。

- `tests/api.test.mjs`：真实 HTTP 登录、教师建号/发布、草稿、权限隔离、评分、人数/平均分、重启持久化、延迟请求不可覆盖已交结果、退出与会话过期。
- `tests/ui.test.mjs`：在 jsdom 中执行实际页面代码，通过真实前端代理和 API 完成表单流程、错误提示、断网重试、草稿刷新恢复、确认提交、逐题反馈、教师统计刷新及账号切换隔离；也验证静态资源和路径限制。

当前通过 17 项 Node 测试（包括分组和子测试），所有 JavaScript 语法检查通过。DOM 测试不是实际浏览器渲染：本环境内嵌浏览器不可用，Edge 控制请求超时，尚未完成真实浏览器视觉、窄屏和原生输入行为检查。详见[本轮验证记录](docs/verification-01.md)。
