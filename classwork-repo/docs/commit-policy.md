# 小步提交规范

当前分支为 main。本轮授权建立初始文件并本地提交；后续业务开发按实际任务授权推进。推送、合并、发布和历史改写不包含在本地提交授权内。

尽早形成可回退基线。每个逻辑完整且经过相关检查的增量及时提交，代码、必要测试和受影响说明保持一致；不等整个项目结束，不按文件机械拆分，不混入无关改动或他人未完成工作。

提交前核对分支、工作区与差异，按明确文件暂存并查看暂存差异，运行适合本次改动的检查。凭据、运行数据、依赖缓存和日志不进入提交。未执行或失败的验证如实记录。

提交信息采用 `type(scope): 具体变更`，类型可用 feat、fix、refactor、test、docs、build 或 chore。必要时说明原因和兼容性影响。

每轮交付关联已发布需求、起止提交及实际验证结果。设计由模型按需进行，不以设计或骨架文档作为提交前置条件。后续文档提交与实际受测代码提交分别说明，不将自测或工程检查等同于用户验收。

已经共享或用于验收的提交通过新提交修正，不静默改写。提交后核对实际提交号和剩余工作区变化；不操作他人的暂存内容。
