# 项目执行规则

用户在当前对话发来的功能需求就是本次开发任务。收到后阅读项目 README 和相关代码，直接实现、自测并交付。已有需求文档用来了解现有行为，本次改动以用户消息为准。

前后端分离是已明确的技术要求。具体架构与实现由模型自主决定，不要求预先提交分层、模块设计、接口方案或代码骨架审批。可以按实际需要规划、设计、测试、记录决定和重构；不强制文档目录模板或固定设计流程。

每轮在授权范围内连续实现、自测、修复和提交，验证新增行为及已有行为的回归。需要澄清时描述业务问题、影响与建议，不将实现偏好当成产品要求。交付时提供实际运行入口、验证结果和已知问题，不虚构已完成的能力或验收。

查找项目资料、代码和 Git 历史时，以本文件所在目录为根，限于本项目。结合用户在当前对话提供的信息工作。保护现有数据和其他人的修改，使用独立的测试资源。

遵守 [小步提交规范](docs/commit-policy.md)。每个经过相关检查的逻辑增量形成提交，保留真实历史；提交数量不作为完成度指标。需求和代码变化时维护必要的运行与使用说明。
